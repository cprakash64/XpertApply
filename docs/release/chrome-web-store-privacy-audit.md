The page scanner **reads locally** the selected application's URL, controls, labels, questions, options, and relevant DOM text. It sends selected question/answer context and workflow state to XpertApply only for application assistance; it does not persist the entire DOM as a general archive. Exact page-derived categories are not assumed to be sent wholesale. The API persists session, answer and tracker artifacts when part of the selected flow. The selected page and its URL are necessary for field mapping, answer preparation, safe autofill and tab/origin authority.

## Browser activity and authority

Manifest required content scripts match first-party XpertApply origins. Employer access is an optional `https://*/*` capability, requested per origin from the side panel after a user click. `apps/extension/src/security/siteAccess.ts` and `background.ts` enforce exact-tab bindings, sender authority, origin checks, host grants and navigation fencing. `tabs.onCreated`/`onUpdated` observe tab transitions to follow the selected application workflow; this is URL/navigation processing and should be selected under the Dashboard's **Web history** category. Source does not show a general browsing-history collector or an unrelated-tab surveillance feature. Redirects/new tabs and embedded ATS frames can be part of the selected application. No page processing on an ungranted employer origin is authorized by the runtime host flow.

## Chrome storage and sensitive state

- `chrome.storage.session`: pending handoffs, active launch, exact-tab view state, prepared session packages and tokens, verified answers/document metadata, frame and grant progress, runtime revival markers. This survives worker suspension, not browser/extension restart. `state.ts` clears session authority on end/expiry/account switch; `background.ts` reconciles startup state and host grants.
- `chrome.storage.local`: API base configuration, side-panel build/environment metadata and sanitized web runtime identity/category/numeric metadata. Code has a compatibility fallback to local when `storage.session` is unavailable; supported production MV3 Chrome uses session for sensitive packages.
- `chrome.storage.sync`: no use found.
- Stored Workday credential ciphertext/credential-shaped keys are excluded from OpenAI payloads by profile projection and credential-minimization checks. For a Workday application, the authenticated `/{session_id}/answers` route decrypts the saved password and returns sensitive answer entries to the extension; this is a deliberate Workday form flow, not an AI/provider transfer. Account export excludes Workday ciphertext (`routes/privacy.py`). Do not claim the extension never handles authentication information: it handles a session token and may handle this Workday answer.

## Retention and controls

`GET /privacy/export` returns account/profile, career, demographics, matches, generated-document metadata/content, application trackers and people-feature records while excluding hashes and Workday credential ciphertext. `DELETE /privacy/account` cleans controlled generated files before account deletion and deletes the user with owned rows. Generated document edit/delete/re-export cleanup is implemented in `routes/jobs.py` and `documents/materialized_files.py`. The qualified production reconciliation found zero generated-volume files and zero orphan candidates; no historical cleanup is needed. Rejected/withdrawn trackers get a seven-day grace period and Undo; `retention_cleanup.py` rechecks eligibility before removal, and `session_service.py` removes related sessions. Do not extrapolate that interval to all account data or external providers. Chrome site grants can be revoked by the user; temporary extension state is purged on session/account changes, browser restart or extension reload.

## Single purpose and Limited Use

Single purpose: **help users prepare, fill, and track job applications using information they provide and information from job/application pages they choose to use with XpertApply.** Page scanning, tab navigation, answers, documents and application tracking are necessary for that purpose; exact-tab authority, authentication, sanitized diagnostics and cleanup are related security/reliability operations. Contact discovery and optional outreach assist a user-requested job application and recruiter-contact workflow. Source and the authoritative production audit establish no sale, personalized advertising, broker/reseller transfer, lending, unrelated profiling or general browser surveillance. No unrelated human reading of extension data was established; the Limited Use certification must continue to restrict it to Chrome's allowed exceptions. No provider retention, training, human-access or contractual guarantees are asserted.

## Remote code and consistency

The manifest points to bundled service worker/content script/side-panel code. The side panel loads local `sidepanel.js`; the extension build packages local JavaScript. Review of `apps/extension/src` found no intended remote executable module, hosted WASM or eval-based code path. API/AI responses are data, not remote extension code. Final package inspection remains part of qualification. The public policy, side-panel disclosure and Store draft all describe selected page/form reading, possible service transmission, five current recipients, manual submission, and optional origin access. Neither blanket local-only claims nor provider retention/training guarantees are made.
