# AUTH-2B Google owner setup

Perform these steps only in the separate owner-configuration stage after the
development checkpoint is reviewed. Do not place credentials in source, Web
environment variables, extension files, tickets, or chat transcripts.

1. Select or create the owner-controlled Google Cloud project.
2. Configure Google Auth Platform branding:
   - Application name: `XpertApply`
   - Homepage: `https://xpertapply.com`
   - Privacy policy: `https://xpertapply.com/privacy`
   - Authorized domain: `xpertapply.com`
3. Configure the audience. Keep the app in Testing and add explicit test users
   for real acceptance; move to Production only after consent-screen and policy
   review.
4. Create an OAuth client of type **Web application**.
5. Register the exact production redirect URI:
   `https://api.xpertapply.com/auth/google/callback`
6. For local acceptance, register the exact local redirect URI:
   `http://localhost:8000/auth/google/callback`
7. Inject these backend settings through the deployment secret/config system:
   - `GOOGLE_OAUTH_ENABLED=true`
   - `GOOGLE_OAUTH_CLIENT_ID=<Web client ID>`
   - `GOOGLE_OAUTH_CLIENT_SECRET=<backend secret>`
   - `GOOGLE_OAUTH_REDIRECT_URI=https://api.xpertapply.com/auth/google/callback`
   - `GOOGLE_OAUTH_WEB_CALLBACK_URL=https://xpertapply.com/auth/google/callback`
   - `GOOGLE_OAUTH_TRANSACTION_TTL_SECONDS=600`
8. The client ID and secret remain backend-only in this implementation. Never
   use `NEXT_PUBLIC_` for either value and never commit the secret.
9. Ensure production Redis is reachable before enabling Google auth; OAuth
   transactions intentionally fail closed when Redis is unavailable.
10. Run the separate real-OAuth acceptance stage before any deployment. Confirm
    the exact callback, consent text, new/returning/link flows, and safe failure
    behavior with owner-controlled test accounts.
